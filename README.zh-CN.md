# Codex 重置提醒（CodexNotch）

一款免费的原生 Mac 小应用：查看 Codex 剩余额度、每周重置倒计时和重置券到期时间，并在公开来源出现新的临时重置预告时提醒你。

[**下载最新版**](https://github.com/Jayzengcodetrip/codex-reset-reminder-mac/releases/latest) · [查看源码](https://github.com/Jayzengcodetrip/codex-reset-reminder-mac) · [English](README.md)

接口中没有官方原帖和公告身份的站方预测，不作为正式重置预告，不生成倒计时，也不会阻断正式公告检查；正式公告本身格式损坏时，应用仍会如实显示检查失败。

> 适用于 **macOS 14 或更新版本、Apple Silicon（arm64）Mac**。这是社区制作的应用，不是 OpenAI、Codex、X 或 NextReset 的官方产品。

## 它能做什么

| 你想知道的 | 应用显示的内容 |
| --- | --- |
| 临时重置什么时候来 | 有明确日期或星期的预告保留各自的倒计时：先倒数至洛杉矶预告日 **00:00:00**，进入当天后倒数至次日 **00:00:00**；这两个边界都是估算，并非官方执行钟点。有明确时刻的预告按其时刻倒数。没有可用日期的预告不生成倒计时，而是在顶部合成一条简短摘要，显示最新原帖摘录及原帖发布时间，并可进入历史查看每条。 |
| 有没有新预告 | 检查完成后显示检查结果；有新公告或实质更新时保留公告记录。在电脑使用期间收到更新，可通过 macOS 通知提醒。 |
| 本周额度还有多少 | 展示账户接口返回的周额度百分比、重置时刻和倒计时；接口提供五小时额度时一并展示。 |
| 重置券有几张、何时到期 | 展示可用次数；展开后查看接口返回的每张重置券到期时间。 |

应用启动时检查一次，此后运行期间约每 **2 分钟**检查公开接口；睡眠唤醒、解锁或网络恢复后会补查。你不在电脑前发现的更新会留在窗口的未读记录中。第一次启动会建立安静的历史基线，不会把既有旧公告全部弹成新通知。窗口可通过鼠标移到屏幕顶部展开，也可用 **⌥⌘N** 收起或恢复。退出应用后，检查也会停止。

提醒依据 [NextReset](https://nextreset.net/) 的公开预告，并补充 [Codex Resets](https://codex-resets.com/) 的官方原帖内容及 [NextReset.org](https://nextreset.org/) 的事件关联数据，并非直接读取 X 的付费实时 API。**提醒速度取决于站方何时捕获和发布消息、网络连接以及本机轮询时间；无法保证 Tibo 发布后五分钟内必达。**洛杉矶是应用使用的参考时区，并非官方指定的重置时区；日期级预告的开始与结束边界都是估算，不是 Tibo 公布的精确执行时间。第一段倒计时以原帖发出时间为起点；即使接口稍后才提供该帖，应用也按当前所在阶段显示，不会重设发帖时间。若接口暂时不可用，应用会保留已取得的记录并提示检查失败，不会把旧记录伪装成刚刚确认的新预告。

## 安装

1. 在 [GitHub Releases 下载页](https://github.com/Jayzengcodetrip/codex-reset-reminder-mac/releases/latest)下载名称含 `macOS-arm64` 的 **DMG**。如果不方便使用 DMG，也可以下载同版 **ZIP**。
2. 打开 DMG，把 `CodexNotch.app` 拖进“应用程序”；ZIP 则先解压，再把应用移进“应用程序”。安装后请从该位置启动，方便登录后自动启动功能正常工作。
3. 先在这台 Mac 上登录并使用 Codex。应用会读取本机 `~/.codex/auth.json`；若你的 Codex 目录不同，需要在启动应用前设置 `CODEX_HOME`。
4. 第一次启动时，按需允许系统通知。想收到桌面弹窗，还要在 macOS 的“系统设置 → 通知”里允许本应用显示横幅。应用设置里有“测试通知”，可用于检查系统通知是否送达。

如果已运行原版 CodexNotch 或此前的本地定制版，请先退出旧应用，避免两份程序同时提醒。本公开版使用独立应用标识，原来的显示偏好与登录项可能需要重新设置。

无需安装 Xcode、Swift 或命令行工具。应用默认尝试注册“登录后自动启动”，你可以在应用设置中关闭；macOS 也可能要求你在“系统设置 → 通用 → 登录项与扩展”中允许它。

**首次打开被 macOS 拦下？** 当前安装包使用 ad-hoc 签名，**尚未经过 Apple Developer ID 签名及公证**。请先确认你下载的是本仓库的 Release，必要时对照随包提供的 `.sha256` 文件。尝试打开应用后，到“系统设置 → 隐私与安全性”找到“仍要打开 / Open Anyway”，再确认打开。这是针对该应用的单次例外；不要为此全局关闭 macOS 安全检查。步骤参见 [Apple 官方说明](https://support.apple.com/en-gb/102445)。

## 看懂提醒

- **有日期的临时重置预告**：只公布当地日期或星期（如“周二”）时分三段显示：① 从 Tibo 发帖时起倒数至洛杉矶周二 `00:00:00`，这是**最早可能窗口的开始**，周一 `23:59:59` 还剩 1 秒；② 周二全天重新倒数至周三 `00:00:00`，周二 `23:59:59` 还剩 1 秒；③ 若周三 `00:00:00` 仍未确认重置，收起这条顶部倒计时；历史仍保留“预告日已过 · 等待确认”。若没有其他有效预告，顶部显示“暂无最新重置预告”。两个边界都是日期估算，不是官方公布的重置钟点。**两段倒计时都不意味着建议提前用尽额度：如果重置推迟，用完额度可能使你在等待期间无额度可用。**卡片显示期间及待确认详情中实时显示“洛杉矶现在：周几 HH:mm:ss”，不显示月、日；macOS 通知里的固定时间标为“通知时洛杉矶”，不会伪装成实时钟。倒计时阶段的北京时间只给对应截止的星期。若原帖明确给出钟点，则按明确时刻倒数。官方宣布已开始直接重置（one-time reset）或发券（banked reset），且能关联到该预告时，就结束对应倒计时。没有其他有效预告时，顶部显示“暂无最新重置预告（今天已重置）”，直到洛杉矶当天结束。来源给出显式关联时优先采用；没有关联时，仅将同一洛杉矶目标日、发放方式相容且唯一的官方预告进行匹配，详情说明这是应用匹配。多条可能匹配或定向补偿不会猜测。时间经过只让过期卡片收起，不会把历史标成已发放；点开、标记已读、账户每周刷新或券数变化也不作为发放证据。取消记录保留在历史中。
- **无日期预告与历史**：多条尚无可用日期的预告合成一条简短首页摘要，显示最新原帖摘录和原帖发布时间；原帖里的“明天”“本周”等相对说法标为发帖当时的语境，不能按本次检查时间重新计算。若较早的无日期预告之后出现可信、范围和发放类型相容的官方重置，该较早预告只退出首页；历史仍保留并标注“后续已有重置 · 本条关联未确认”，附有查看入口。本账户后来收到相容的重置券时，较早预告也只退出首页，历史改为显示“本账户已收到重置券 · 本条关联未确认”和具体到账时间。这两种情况都不自动认定原预告完成，也不强行关联；较新的预告继续显示，旧预告后续补上日期则重新显示独立倒计时。
- **简短完成回复**：对于“Done and dusted”等简短确认，只有它引用的链接确实指向已有、来源已核验且发放类型相容的官方重置预告时，才识别为重置完成。计时使用完成帖的发布时间；孤立的“完成了”、无法核实的链接、定向补偿或相冲突的类型不会被当作全局重置。
- **最近一次发放**：经过时间与预告摘要或倒计时分开显示，即使今天已收到重置券且没有新预告，也会继续显示；不足一天用 HH:mm:ss，满一天用 N天HH:mm:ss。公开官方发放消息的起点标为“距上次重置已过”，只表示官方开始发放，不保证本账户到账。本账户重置券接口返回已发生的精确 `granted_at` 时，可改为显示“距本账户收到重置券已过”，并标明需要自行使用。选择较新的可信发放时间显示，不把券数变化、每周额度变化、接口检查时间或未来的到账时间当作发放证据；没有可信起点时不显示经过时间。另有经确认的账户额度恢复时，可以显示该账户恢复计时，具体规则见下一项。
- **人工确认完成**：如果实际已重置而自动识别尚未跟上，可点击预告时间旁的“确认已重置”。只结束这条预告，距上次重置从点击时刻重新计时，人工确认来源保留在历史中，首页计时下方不显示人工确认说明；不会改写官方公告或清除未读。无日期或已离开首页的预告也可在历史详情中单独确认。保存成功后才生效，重启和接口刷新不会重开；同帖后续修订继续保留但不重放通知。误点可在详情中“撤销人工确认”，恢复依据现有官方和账户证据的展示。人工确认不代表官方公布了该完成时间，也不执行账户重置或使用重置券。
- **根据账户额度恢复识别完成**：按账户保存上一次有效的周额度；实际已用比例从非零变成 0 后，再由下一次有效检查确认恢复。读取重置券的真实兑换时间，核对原定周重置边界，并可关联首次检测前 24 小时至后 30 分钟内唯一且相容、已实际发布的官方直接重置消息，区分手动用券、正常周重置和官方临时重置期间恢复。券记录缺失、原因重叠或无法确认时，显示“本账户额度已恢复 · 方式待确认”，暂时保留上一次已确认的计时；后续证据可以补充或纠正原因。确认后在“距上次重置已过”下面标明来源：手动用券按兑换完成时间计时，其余按首次检测到恢复的时间计时，不冒充精确到账时间。首次启用只建立基线，不能追溯启用前的恢复；两次检查之间重置后又消耗到未满的情况，这条规则可能观察不到。账户判断不改动预告识别、预告记录、未读状态或公告通知。
- **“已检查接口，暂无新重置预告”**：表示这一轮检查没有发现新的预告，**不代表之前尚未完成的预告消失**；已有倒计时仍会显示。检查正在进行或失败时，界面会显示对应状态。
- **本周重置和重置券**：来自你自己的账户数据，与临时福利预告是不同信息。重置券的可用次数与到期时间可能因账户接口状态而暂时缺失；不要把临时重置预告等同于获得了一张重置券。

## 数据与隐私

| 数据 | 读取位置 / 请求地址 | 用途 |
| --- | --- | --- |
| Codex 登录令牌与账户 ID | 本机 `CODEX_HOME/auth.json`，默认 `~/.codex/auth.json` | 仅用于请求 `chatgpt.com/backend-api/wham/usage` 和 `chatgpt.com/backend-api/wham/rate-limit-reset-credits`。 |
| 公开预告 | `https://nextreset.net/api/status` 与 `https://nextreset.net/api/resets` | 检查预告、更新和状态；请求**不附带 Codex 登录令牌**。 |
| 发放及预告关联 | `https://codex-resets.com/api/v1/resets?limit=100` 与 `https://nextreset.org/api/v1/events.json` | 识别官方已开始直接重置/发券及关联证据；匿名 GET，不发送账户数据。补充来源失败时保留已取得的发放证据。 |
| 简短确认的引用链接 | 官方完成帖中的 `https://t.co/` 短链 | 每轮最多 4 条匿名 HEAD 请求，限时读取跳转地址；仅接受跳到官方 `thsottiaux` 原帖，不请求落地页面，不携带登录令牌、Cookie 或账户数据。失败不影响其他公告检查。 |
| 任务活动与最近对话标题 | 本机 Codex sessions 文件和 `state_5.sqlite` | 展示本机任务状态与简短标题。 |
| 已读和公告历史 | 本机 `~/Documents/Codex/QuotaReminderState/announcements.json` | 重启后保留公开公告及未读状态；不包含账户令牌或额度响应。 |
| 本账户重置券到账时间 | 本机 `~/Library/Application Support/CodexNotch/account-reset-receipts.json` | 按账户隔离保存接口返回的精确 `granted_at`、标题和说明，供经过时间与历史提示使用；账户 ID 只用作本地哈希键，文件不保存令牌，也不向公告站点发送账户数据。 |
| 本账户额度恢复记录 | 本机 `~/Library/Application Support/CodexNotch/account-quota-recoveries.json` | 保存额度比较基线、观测区间和归因证据；账户与券标识使用哈希，不保存令牌或原始账户 ID，不发给公告站点。 |
| 手动检查应用更新 | GitHub 公开 Release 元数据 | 仅在手动检查时读取版本信息。 |

账户额度使用 ChatGPT 的内部接口，接口结构和可用性可能变化。请不要在 issue、截图或日志中上传 `auth.json`、令牌、账户 ID 或私人对话内容。应用不提供云同步、远程推送，也不需要付费 X API。

## 从源码构建

需要 macOS 14+、Xcode 15 / Swift 5.9 或更新版本：

```sh
swift test
./scripts/build_app.sh
open dist/CodexNotch.app
```

创建待分发的 DMG、ZIP 与各自的 SHA-256 文件：

```sh
./scripts/release.sh
```

发布脚本会运行测试、构建应用并检查签名与磁盘映像。通过脚本检查不等于苹果公证，也不能替代在真实 Mac 上验证通知、睡眠唤醒、悬停窗口和安装体验。
