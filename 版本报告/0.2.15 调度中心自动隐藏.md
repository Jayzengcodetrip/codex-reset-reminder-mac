## 问题

用户在 Mac 调度中心切换桌面或全屏软件时，展开的顶部提醒卡片挡住了桌面缩略图。原窗口采用 `.stationary`，这正是系统定义的“调度中心中仍保持可见”规则。

## 改了什么

- 将顶部小窗的窗口集合规则改成 `.transient`，请求系统在调度中心隐藏小窗和透明悬停区域，退出后恢复正常窗口处理。没有增加额外开关、持续轮询、辅助功能权限或私有系统调用。
- 保留跨桌面、全屏辅助窗口、跨应用、原置顶层级和既有短时恢复队列。没有修改公告、已读、计时、账户数据或用户的长期显示偏好。
- 新增窗口策略自检和回归约束，明确自动检查的是配置及调度，不代表真实调度中心过渡已经验收。
- 发布脚本在新 ZIP、DMG 及校验文件通过后自动保留最新两版标准名安装包；保护备份、报告、历史、未知文件与符号链接。外部交付根需要显式指定。
- 构建脚本允许显式使用本机已有 SDK/构建方式，默认不变。本次使用 native + SDK 26.5，未修改系统工具链选择。

依据：[Apple 对 transient 的定义](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct/transient)、[stationary 的定义](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct/stationary)。

## 没有验证

- **真实调度中心隐藏与恢复全流程尚未完成验收。** 本轮工具能读取普通应用及顶部卡片，但获取 Dock/Mission Control 系统界面返回 `timeoutReached`，无法完整观测用户截图中的全屏概览。因此没有将顶部缩略图点击无遮挡、动画中无短闪、概览驻留后的延迟重排、实际手势快速进出、退出后悬停重入写成通过。
- 新窗口规则有 Apple 官方定义和 SDK 依据；这不能替代上述真实系统过渡的操作结果。后续应使用用户原来的手势进入调度中心，停留顶部超过一秒并切换全屏软件，再验证悬停可正常打开。
- 本机完整 XCTest 未运行成功：默认 `swift test` 因 SDK 27.2 缺 `SwiftUIMacros.StateMacro` 失败；改用 SDK 26.5/native 后应用可编译，但测试因缺 `XCTest` 模块失败。本机交付阶段没有本版远程 CI 结果，不沿用 v0.2.14 的 459 项结果；后续公开发布阶段另行记录。
- 本轮未完整测试真实通知送达、登录启动、锁屏唤醒、多显示器切换、干净机器首启及其它 macOS 版本。
- 旧 local-acceptance 测试包、不同 Bundle ID 的旧应用及用途含糊文件不属于本轮明确交付清理范围，继续保留。
